## What's changed

**`Net.Agora.Voice.Android` debuts**: .NET for Android / .NET MAUI bindings for Agora's Voice SDK,
generated from
[`io.agora.rtc:voice-rtc-basic` 4.6.3](https://central.sonatype.com/artifact/io.agora.rtc/voice-rtc-basic)
on Maven Central — the same RTC engine as `full-rtc-basic`, built without the video pipeline: a
~28 MB `.aar` against full's ~48 MB, for apps that never show or send video.

**`Net.Agora.Signaling.Android` debuts too**, at its own version **2.2.6.1**: bindings for
[`io.agora:agora-rtm` 2.2.6](https://central.sonatype.com/artifact/io.agora/agora-rtm) — Agora's
Signaling (RTM 2.x) SDK, under the **`Agora.Rtm`** namespace, self-contained (libaosl ships
inside the `.aar`), coexisting with either RTC package. From this train on, each package
publishes at its own version line and a tag is just the train's label — see the release workflow.

`Net.Agora.Video.Android` is unchanged apart from the release mechanics.

> **Package versions are `<native artifact version>.<binding revision>`.** `4.6.3.2` is the 4.6.3
> native artifacts, binding revision `2`. The fourth component belongs to this repository and
> advances when the bindings or packaging change while the native artifact stays put.

## Contents

### Which package?

| Package | Native artifact | Use it when |
| --- | --- | --- |
| `Net.Agora.Video.Android` | `io.agora.rtc:full-rtc-basic` | The app shows or sends video (also carries the full audio surface). |
| `Net.Agora.Voice.Android` | `io.agora.rtc:voice-rtc-basic` | Audio only — the smaller engine. |

Pick **one**: both `.aar`s carry the same Java classes, so referencing both fails the build at dex
merge — mirroring Agora's own artifacts. Both bindings expose the same **`Agora.Rtc`** namespace,
so an app switches packages without touching code; the video entry points the shared Java API
layer declares still compile against the Voice binding and answer error codes at runtime, exactly
as they do on Agora's own voice SDK.

```csharp
using Agora.Rtc;

var config = new RtcEngineConfig { MContext = context, MAppId = "<APP_ID>" };
var engine = RtcEngine.Create(config);

engine.EnableAudio();
engine.JoinChannel(token: null, channelId: "my-channel", optionalInfo: null, uid: 0);
```

**`voice-rtc-basic`, deliberately not `voice-sdk`** — the same reasoning as `full-rtc-basic` vs
`full-sdk` in [4.6.3.1's notes](4.6.3.1.md): the umbrella artifact aggregates optional plugins
this package exposes no API for. `voice-rtc-basic` carries exactly one dependency
(`io.agora.infra:aosl`), which the package also ships.

Most apps want the cross-platform client instead:
[`Net.Agora.Voice`](https://github.com/sbokatuk/Net.Agora), which wraps this package and its iOS
sibling behind one API — awaitable join, .NET events, speakerphone routing, volume indication.

## Tests

The existing suites now run per package — everything still against the packed `.nupkg`:

- **Package tests** assert both packages' layout (binding assembly and native `.aar` per target
  framework, with `voice-rtc-basic-*.aar` in Voice) and API surface — the same core `Agora.Rtc`
  types, since the voice `.aar` ships the same shared Java API layer.
- **Emulator smoke tests** gained a package axis: the Voice legs drive create/audio/mute/destroy
  against the packed Voice package (the video checks are compiled out — the voice engine answers
  error codes to them by design) on the two extreme target frameworks.
