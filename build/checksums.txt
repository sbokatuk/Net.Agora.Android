# SHA-256 of every native artifact this repository binds, keyed by
# <groupId>:<artifactId>:<version>. Verified by build/verify-artifacts.sh, which downloads each
# coordinate from the repository the binding resolves it from and compares.
#
# Why the bytes are pinned and not just the version: a Maven coordinate is a mutable pointer. A
# re-published artifact keeps its version, and AndroidMavenLibrary performs no content check of
# its own — what the .NET Android SDK calls Java dependency verification is a class-graph
# completeness check (XA4241/XA4242), not a digest. Agora publishes no checksum manifest of its
# own to defer to.
#
# The com.github.netless-io artifacts need this most: JitPack builds them on demand from a git
# tag, and netless has re-tagged before, so the same coordinate can serve different bytes.
# DSBridge-Android's "version" is literally a tag name (nl_dsb_v3.0.4) and it is bound
# (Bind=true), so a moved tag would change the generated public API — see the Whiteboard csproj.
#
# After bumping a version in Directory.Build.props, refresh the line with:
#
#   ./build/verify-artifacts.sh --print
#
# and check the new hash against what the artifact should be before committing it — recording
# whatever was served defeats the point if you have not looked at why it changed.
#
